## 배포 후 INVALID_TOKEN 대응

- 사용자가 배포본에서 `401 INVALID_TOKEN`을 보고했다. 로컬/Azure의 tenant, audience, scope가 동일하고 API 앱은 v2 토큰을 발급하도록 설정되어 있음을 확인했다.
- 토큰을 보내지 않은 실서비스 요청도 `INVALID_TOKEN`이므로 SWA가 API에 내부 Authorization 값을 넣는 동작과 일치한다. 관련 Azure 이슈: https://github.com/Azure/static-web-apps/issues/275
- 클라이언트와 API가 `X-Runner-Authorization` 전용 헤더로 앱 토큰을 전달/수신하도록 변경했다. 서명·issuer·audience·만료·tenant·scope 검증을 유지하고 플랫폼 Authorization은 사용자 인증에 사용하지 않는다.
- 검증: API 테스트 27개(플랫폼 헤더 주입 및 잘못된 토큰 거부 포함), 클라이언트 API 테스트 8개, 양쪽 lint/build 통과.
- 수정 커밋 `cfab5ef` 배포 성공: https://github.com/Seungwon-2/vibe/actions/runs/43804778223
- 배포 후 확인: 사이트 HTTP 200. `/api/runs/best`, `/api/runs`, `/api/leaderboard`는 앱 토큰 없이 `UNAUTHENTICATED`, 잘못된 전용 헤더 토큰은 `INVALID_TOKEN`을 반환한다. 전용 헤더 처리 및 인증 경계 반영을 확인했다.
- 실제 로그인된 계정의 저장·조회 성공 여부는 사용자의 새로고침 후 재확인 필요. 해당 확인 전 클라우드 사용자 테스트 완료로 표기하지 않는다.

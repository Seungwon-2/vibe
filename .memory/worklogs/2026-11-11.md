# 작업일지 · 2026-11-11

## 오늘 확인한 내용

- VS Code를 다시 실행한 뒤 Azure CLI가 정상 동작하는지 확인했다. 로그인된 대상은 회사 Entra 테넌트와 `CR-Project-01` 구독이었다.
- 활성 배포 계획은 `.memory/plans/2026-11-11-azure-swa-github-deployment.md`, 현재 작업은 P02-T02 Entra 앱 등록이다.
- 기존 단일 테넌트 `Stella Runner API` 등록을 재사용하고 `Stella Runner SPA` 등록을 구성했다. SPA는 API의 `access_as_user` 단일 delegated scope만 요청하도록 되어 있다. Graph 권한이나 SPA 비밀 값은 추가하지 않았다.
- 테넌트 전체 동의 요청은 현재 계정에 필요한 Entra 디렉터리 권한이 없어 실패했다. 현재 확인 기준으로 동의 grant는 아직 없다. Azure Contributor와 Entra 관리자 권한은 별도 권한 체계다.
- 사용자는 다른 팀이 Contributor 권한으로 SWA와 Cosmos DB를 연결해 배포한 사례와 비교해 현재 설계가 과도한지 질문했다. 확인 결과 관리자 동의는 Cosmos 연결 자체 때문이 아니라, 현재 선택한 MSAL SPA → 사용자 API 토큰 → 자체 API scope 검증 구조에서 요구된다.
- 더 단순한 대안으로 SWA 기본 Entra 인증(`/.auth` 경로)과 관리형 API의 `x-ms-client-principal` 연결을 검토할 수 있다. 이 방식에서는 앱 자체의 API delegated scope가 필요하지 않을 수 있지만, 회사 테넌트 사용자만 허용하는 방법과 사용자 표시 이름/ID claim 사용 가능 여부를 확인해야 한다.

## 현재 상태와 중단 지점

- Entra API·SPA 등록과 redirect/scope 구성은 되어 있다. 관리자 동의는 미완료이며, 동의 요청을 관리자에게 넘기기 전에 인증 구조를 다시 비교하기로 했다.
- Azure 리소스 생성이나 배포, Cosmos 비밀 설정 변경은 오늘 진행하지 않았다.
- 코드·테스트 상태는 앞선 T02 작업에서 확인했다. 현재 T02는 관리자 동의 검증 전이므로 완료 처리하거나 다음 작업으로 넘기지 않았다.

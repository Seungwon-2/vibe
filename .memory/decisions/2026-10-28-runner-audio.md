# Decisions: Runner Audio

- Date: 2026-10-28
- Status: Confirmed

## D01. Music Structure and Style
- **Chosen**: One menu track and four runner tracks, one for each biome: dawn city, moonlit forest, crystal mine, and cloud-top skyway. Use bright, cheerful fairytale music led by piano, with biome-specific accompaniment and mood. Use Pokémon Diamond/Pearl road music, including Route 209, only as a broad style reference for the user's preferred adventurous road-game feeling and memorable melodies.
- **Rationale**: Distinct music supports the existing four biome transitions while keeping the game's musical identity warm and cohesive. The reference communicates the desired direction; all melodies and arrangements in the game must be original.

## D02. Music Assets and Looping
- **Chosen**: Store audio files in the project for offline playback and choose loops about one to two minutes long. Prefer original audio generated by deterministic project scripts; do not include third-party recordings, melodies, soundfonts, or samples in the generated assets.
- **Rationale**: Local assets avoid network and URL availability issues; original generated material avoids unclear reuse rights and can be regenerated from project source.

## D03. Music Screen and Transition Behavior
- **Chosen**: Play menu music on the main menu, character selection, ranking, and result screens. Play biome music only during the run. Begin menu music after the first click or touch, when browser audio playback is allowed. Fade between menu and run music as the 3-second countdown begins; crossfade at biome boundaries. Use a 700ms fade for transitions.
- **Rationale**: Browser autoplay restrictions require a user gesture, and crossfades make screen and biome changes feel continuous.

## D04. Pause and Run-End Behavior
- **Chosen**: On pause, fade out music and resume it from the same position. On run completion, fade out the run track and use menu music for the result screen.
- **Rationale**: The run remains musically continuous while paused, and results return to the established menu-screen music context.

## D05. Sound Effects
- **Chosen**: Use soft, clear piano, bell, and light-percussion sounds for jump, double jump, slide, coin, +3-second pickup, +20-second gate, hit, fall, and primary button interactions. Give Hiyori's defense activation its own protective effect. Vary coin-chime pitch during consecutive pickups; use an ascending chime for time pickups and a fuller fanfare for gates. Keep hit and fall sounds gentle and non-startling.
- **Rationale**: Distinct cues communicate gameplay events while matching the pastel fairytale presentation.

## D06. Audio Controls and Defaults
- **Chosen**: Provide mute and separate music/effects volume controls in settings accessible from both the main menu and pause screen. Start with audio enabled, music at 60%, and effects at 80%. Persist preferences in the browser.
- **Rationale**: Separate, persistent controls let players tune music and effects without adding complexity to gameplay.

## D07. Credits and Asset Records
- **Chosen**: Provide an `음원 크레딧` entry from the main menu and document every included audio asset's provenance in the repository. Generated assets must name their composition/rendering scripts; if an external asset is approved in a later change, record its source and license.
- **Rationale**: This makes asset origin discoverable in-game and preserves regeneration details with the offline assets.

## D08. Existing Project Context
- **Chosen**: Implement audio as a new runner-audio feature; the current source has no audio system or audio assets, and settings are not currently available. Reuse the existing main menu and pause screen as settings entry points.
- **Rationale**: Repository inspection found no existing audio integration to extend and confirmed the two requested access points.

## D09. Original Audio Generation Route
- **Chosen**: Generate the five music files and ten sound effects locally with deterministic Node.js scripts and built-in modules, then store the output WAV files in the repository. Use a piano-like synthesized timbre without third-party samples; audition the result before integrating playback.
- **Rationale**: This produces files that work offline and are reproducible from the repository. The result is piano-like synthesis rather than an acoustic piano recording, so its timbre needs an explicit listening review.

## D10. Music Reference Timing
- **Chosen**: Defer background-music composition and integration until the user provides a preferred audio reference file. Start development with sound effects; treat all generated music drafts as unapproved and exclude them from the effects catalog.
- **Rationale**: The first generated music direction did not match the user's intended feel, so effects can proceed independently while the preferred reference is prepared.

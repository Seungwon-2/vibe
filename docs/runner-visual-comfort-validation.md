# 스텔라 러너 — 화면 피로도 개선 비교

- 작업일: 2026-11-17
- 기준: project02 로컬 개발본. 이번 변경은 아직 Azure에 배포하지 않았다.
- 상태: 화면 프리셋 구현과 자동 검증 완료. 실제 브라우저 성능 측정·시각 확인 및 사용자 체감 비교는 대기.

## 적용한 변경

| 항목 | 편안한 화면 (새 기본값) | 기존 효과 (비교용) |
| --- | --- | --- |
| 원경 이동 | 정지 | 실제 이동 거리의 0.15배 |
| 중경 이동 | 정지 | 0.4배 |
| 바닥 이동 | 실제 이동과 동일 | 실제 이동과 동일 |
| 배경 | 배경에만 차분한 색과 낮은 장식 불투명도 적용 | 기존 색·장식 유지 |
| 화면 전체 연출 | 게이트 선·거대화 반복 발광·추락 흔들림 없음 | 기존 연출 |
| 장착 궤적 | 작은 점을 적게 표시, 흰 반짝임과 주변 발광 제거 | 기존 반짝임 |
| HUD | 효과 종류·남은 시간 유지, 보너스 문구 이동 제거 | 기존 표시 |

- 일시정지의 **화면 효과** 선택에서 바꿀 수 있다. 같은 런을 멈춘 상태에서 바꾸며 게임을 재생성하지 않는다.
- 설정은 이 브라우저에 저장한다. 저장소가 차단돼도 현재 선택은 적용되고 게임을 막지 않는다.
- 운영체제/브라우저의 `prefers-reduced-motion`이 켜져 있으면 기존 효과를 골라도 편안한 화면을 적용하고 장착 궤적은 숨긴다.
- 캔버스 전체에 어둡게 하는 필터를 씌우지 않는다. 장애물·아이템·캐릭터의 색과 판정은 별도로 유지한다.
- 편안한 화면의 배경 이동은 소수 좌표를 유지한다. 느린 레이어를 매번 정수로 버리면서 0px/1px 이동이 번갈아 발생하던 표현을 피한다. 실제 프레임 시간 측정과는 별개의 좌표 정밀도 보정이다. 비교용 기존 효과는 원래 반올림 방식(소수 버림)을 유지한다.
- 실제 기본/최고 속도, 부스트 배율, 점프 물리, 충돌 상자, 코인/장애물 배치와 랭킹 정렬 규칙은 유지한다. 후속 요청으로 거대화 종료 직후 일반 장애물 보호 1초를 추가했다. 실제 속도와 난이도의 추가 변경은 비교 의견을 받은 뒤 별도로 결정한다.

## 후속 피드백: 이동 방향·경계·거대화 종료

- 커밋 `eb2b1a5`: calm 원경·중경은 고정하고 바닥만 장애물과 같은 월드 거리를 따른다. 두 모드 모두 바닥의 촘촘한 사선 격자를 넓은 수직 이음새로 바꿨다. 바닥 무늬의 반복 길이는 타일 폭에 정확히 맞춘다. 실제 이동 부호가 반대였다고 확인된 것은 아니며, 지각상 역방향·떨림 개선은 직접 비교가 필요하다.
- 배경의 이중 투명도를 일부 완화하고, 장애물 테두리·측면·면 명암과 코인의 공통 금색 재질·짙은 테두리·고정 하이라이트를 보강했다. 테마별 실루엣, 슬라이드 통로, 표시 범위와 판정 크기는 유지한다. 새로운 반짝임 애니메이션이나 렌더 해상도 증가는 없다.
- 커밋 `94bf343`: 거대화 자연 종료 후 **일반 장애물에 1초 보호**. 두 모드에 적용하며 생명·시간·패시브를 소모하지 않는다. 낭떠러지는 기존 즉사/히요리 방어 규칙을 유지한다.
- 보호 시간은 `giantRecoveryRemainingMs`로 따로 저장한다. `giantRecoveryMs: 1000`을 중앙 설정에서 변경할 수 있다. 종료를 넘긴 프레임의 시간도 차감하고, 정지 중에는 멈추며 이어하기에 보존한다. 옛 저장에 필드가 없으면 보호 없음으로 처리한다. 새 거대화·최종 종료·히요리 낭떠러지 복귀에서는 초기화한다.
- 기존 거대화 HUD 슬롯에 ‘보호’를 표시해 상태에 따른 HUD 크기 변화를 막았다. 설명서에서 몸집과 속도를 모두 2.5배라고 잘못 표현하던 문구도 바로잡았다(속도만 2.5배).
- 최종 자동 검증: **60개 파일 / 353개 테스트**, lint, build 통과. 관련 집중 검증은 가시성·캐시 31개, 보호·저장·HUD·설명서·판정 58개다. 기존 Vite 청크 경고와 테스트 환경의 미디어 재생 미구현 안내는 남아 있다.
- 추가 로컬 확인: 기본 화면에서 바닥·장애물 이동감, 네 테마의 코인/장벽/슬라이드 경계, 거대화 자연 종료 뒤 1초 보호와 그 이후 피격, 정지·새로고침 후 이어하기. 시각 확인과 실기기 프레임 시간은 여전히 미검증이다. 원격 브라우저 실행의 자동 승인 거부와 native pipe 연결 실패를 우회하지 않았다.

## 배경 전환 작업의 이동

이전 코드는 테마가 바뀌는 update에서 Graphics로 레이어 세 장을 그려 `generateTexture`를 호출했다. 현재는 카운트다운 전에 해당 모드에서 필요한 텍스처를 준비하고 전환 중에는 그 텍스처를 재사용한다.

| 구조적 검증 항목 | 이전 코드 | 현재 자동 검증 |
| --- | --- | --- |
| 주행 중 테마 전환의 배경 텍스처 생성 | 3장/전환 | 0장/전환 |
| 무한 모드 초기 준비 | 첫 테마 3장 | 네 테마 12장 |
| 스토리 모드 초기 준비 | 고정 테마 3장 | 고정 테마 3장 |
| 화면 모드 두 종류 방문 시 최대 레이어 수 | 교체 시 생성·삭제 | 무한 24장 / 스토리 6장 |
| 장면 종료 | 활성/나가는 세트별 삭제 | 소유 텍스처를 한 번씩 삭제 |

이는 **작업 발생 위치와 호출 횟수의 검증**이다. FPS 향상이나 멈춤 시간 단축을 측정한 결과는 아니다. 초기 준비 시간 및 텍스처 메모리 증가와 실제 플레이 중 이득을 기기에서 비교해야 한다. 480×540 RGBA 레이어 24장의 단순 픽셀 데이터는 약 23.7MiB이며 실제 GPU 사용량은 브라우저/드라이버에 따라 다르다. 스토리는 사용하지 않을 다른 테마를 미리 만들지 않는다.

## 자동 검증

- 전체 프런트엔드 테스트: 60개 파일 / 347개 통과. 마지막 소수 좌표 보정 후 관련 배경·장면 테스트 17개 추가 통과. 최종 build(타입 검사 포함)·lint 통과. 기존 Vite 청크 크기 경고는 남아 있으며, 이 경고 자체를 런타임 프레임 드롭의 원인으로 확정하지 않는다.

- 프리셋: 기본값, 저장 왕복, 잘못된 값/버전, 저장 차단, OS 동작 줄이기 우선.
- 일시정지: 모드 변경 후 정지 유지, 재진입 시 저장값 복원.
- 엔진: 화면 모드 변경으로 Phaser 인스턴스를 새로 만들거나 입력/저장 상태를 바꾸지 않음.
- 배경: 바닥 이동 거리 유지, 테마 위치 유지, 주행 중 텍스처 생성 없음, 모드 재방문 시 재사용, 종료 중복 호출 시 자원 중복 삭제 없음.
- 궤적: 편안한 화면의 작은 점/기존 효과의 반짝임 분리.
- 추락: 두 모드 모두 동일한 결과·코인·거리와 종료 경계 보존, 편안한 화면에서 카메라 흔들림 없음.

## 이번 환경에서 측정하지 못한 것

- 격리 브라우저 원격 디버깅 실행은 도구 자동 승인에서 `blocked by policy`로 거부됐다. 추가 허용 사유는 제공되지 않았다.
- 연결 브라우저 도구는 native pipe 연결 실패로 사용할 수 없었다.
- 따라서 p50/p95/p99 프레임 시간, 드롭 프레임 수, 테마 전환 CPU/GPU 시간, 실제 화면 캡처, 눈 피로·멀미 개선 여부는 이번 변경에서 확인하지 않았다. 이전 세션의 화면 캡처를 이번 검증으로 재사용하지 않는다.
- 이전 피드백 회귀 P03-T04와 이번 T02의 브라우저 측정 조건은 완료로 처리하지 않는다.

## 로컬에서 비교하는 순서

1. http://127.0.0.1:5175/ 를 연다. 이 개발 프로세스만 로컬 게스트 모드이며, 환경 파일과 배포본 회사 로그인은 변경하지 않았다.
2. 같은 캐릭터·스토리 스테이지로 시작한다. 첫 실행 기본값은 편안한 화면이다.
3. Esc 또는 일시정지 버튼 → **화면 효과**에서 기존 효과/편안한 화면을 바꾸고 같은 런을 계속한다.
4. 배경을 따라 눈이 끌려가는지, 부스트 진입·종료 시 부담, 장애물과 바닥 경계가 빨리 구분되는지 비교한다. 불편함을 참으며 긴 테스트를 할 필요는 없다.
5. 브라우저 성능 기록은 시작 로딩과 정지 구간을 분리해 일반 주행·부스트·테마 전환별로 수집한다. 평균 FPS와 함께 느린 프레임, GC/저장 순간도 확인한다.
6. 캐릭터/코스/화면 효과/브라우저/기기와 불편한 시점 또는 거리를 함께 기록한다.

## 다음 판단

먼저 실기기에서 화면 프리셋의 체감과 프레임 기록을 확인한다. 측정된 병목만 추가로 고치고, 그 결과에 따라 부스트의 실제 배율·진입/종료·장애물 간격을 검토한다. 이번 수정만으로 프레임 드롭이나 멀미가 해결됐다고 판단하지 않는다.
